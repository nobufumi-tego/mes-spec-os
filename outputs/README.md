# outputs/

`/MES仕様書` コマンドが生成した仕様書 / RFP 一次稿が保存される場所です。

## ファイル構成（正本＋履歴の 2 層）

```
outputs/
└── MES仕様書/
    ├── <YYYYMMDD>_<案件名>.yaml   ← 正本・構造化データ（常に最新）
    ├── <YYYYMMDD>_<案件名>.md    ← 正本・RFP 一次稿（人間可読）
    └── 履歴/
        ├── <案件名>_v01_<日時>_Stage1.yaml   ← Stage 完了ごとの自動コピー
        ├── <案件名>_v02_<日時>_Stage2.yaml
        └── <案件名>_v03_<日時>_Stage4.yaml   ← 確定版は .md も対で保存
```

## 世代管理（バージョン）

- 正本は常に最新版。Stage が完了するたびに `履歴/` へ版番号＋日時付きのコピーが自動保存されます
- 各ファイルの冒頭には改訂履歴表（版 / 日時 / 変更内容）が追記されるので、単体でメール添付しても版が追えます
- **前の版に戻したいとき**：Claude に「案件A を v02 に戻して」と頼むと、履歴のコピーを正本に複写して戻します（履歴は消えません）

## ENAA 出典記載

すべての出力ファイルの末尾には ENAA 出典が**自動で付記**されます。
これは ENAA「MES/MOM 導入のための標準業務一覧」の利用条件（著作権表示必須）に基づく仕様で、削除しないでください。

## Git の取り扱い

**あなたが生成した仕様書は git に記録されません**。

- 追跡されるのは同梱サンプル（マルヨシ精工）とこの README のみ
- 実案件の生成物（`履歴/` 含む）は顧客名・ライン構成・原価等の機密を含み得るため、`.gitignore` でデフォルト除外
- 世代管理は上記のファイル名方式で行うため、通常 git は不要です
- （上級者向け）どうしても git でも管理したい場合は、リモート設定がないことを確認した上で
  `.gitignore` の `!outputs/MES仕様書/...` の並びに自分のファイルを追加してください
